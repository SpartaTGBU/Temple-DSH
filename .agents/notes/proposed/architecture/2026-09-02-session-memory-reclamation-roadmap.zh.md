# Agent Note: 会话内存回收路线图

Status: proposed

[English](2026-09-02-session-memory-reclamation-roadmap.md) | 中文

## Problem

会话内存相关包提供测量、压力检测、候选项选择与安全的缓存释放，但实时 `Session` 仍拥有完整的仅追加事件日志。当前命名容易让规划与分析看起来像物理回收：驻留策略把操作委托给执行器，而已交付的执行器只释放可重建缓存；日志分层与分片回收模块只计算假设收益，不改变会话。维护者需要一份当前决策记录，把这些基础能力与真正能从堆中移除日志行的机制区分开。

## Present state

| 领域 | 已交付行为 | 边界 |
|---|---|---|
| 测量 | [内存计量器](../../../../packages/util/memory-meter/README.zh.md)估算序列化事件字节数、对会话排序，并包含宿主 RSS／堆基准测试。 | 该估算不是精确的保留大小遍历。 |
| 压力 | [内存压力检测器](../../../../packages/runtime-diagnostics/memory-pressure/README.zh.md)发出级别转换事件并暴露当前级别。 | 它检测压力，但绝不卸载内存。 |
| 驻留策略 | [驻留策略](../../../../packages/session/session-residency/README.zh.md)对空闲会话排序、排除开放轮次，并把选中的候选项委托给一个执行器。 | 它既不拥有存储生命周期，也不实现透明再水合。当前没有已交付 profile 组装这条包链。 |
| 缓存释放 | [缓存释放执行器](../../../../packages/session/session-residency-cache-release/README.zh.md)调用 `Session.releaseCaches()`，丢弃事件快照、派生消息投影与请求上下文折叠。 | 这只物理回收易失缓存；完整事件日志与 `Session` 仍然驻留。 |
| 派生历史 | [会话 API](../../../../docs/subsystems/session.zh.md)暴露 `deriveMessagesShared()` 与可延迟重建的缓存。 | 共享数组避免每次调用时复制；它不缩减驻留日志。 |
| 持久化 | [持久化 seam](../../../../packages/session/session-persistence/README.zh.md)为显式冷恢复加载持久日志，且其后端可以在磁盘上打包分片运行。 | 实时存储项不能变为休眠状态并在访问时自行故障调入。磁盘打包不会压紧驻留事件数组。 |
| 分析 | 内存计量器的 `chunk-reclaim` 与 `log-tiering` 入口估算假设的已打包分片字节数与冷前缀字节数。 | 两个分析器都是纯函数且不修改数据。它们回收零字节。 |
| 长期记忆 | [原生 MemPalace 能力](../../../../docs/subsystems/memory.zh.md)召回并捕获提供方无关的语义记忆。 | 它独立于会话日志驻留，且不是驱逐或再水合后端。 |

已交付 seam 是有用的基础，但它们并非端到端的驻留日志驱逐功能。普通持久化恢复证明持久日志可以重建会话；它没有证明当现有 agent、scope 或调用方可能保留旧 `Session` 对象时可以透明再水合。

## Proposal

只把整会话驱逐与透明再水合作为当前有效的物理回收提案。只有具名的长时间运行组合通过代表性基准测试证明缓存释放后驻留日志仍是显著压力来源时，才实现该提案。实现应位于现有 `ResidencyExecutor` 之后，但还需要显式的存储／agent 生命周期约定：选中的已闭合空闲会话到达持久性检查点，释放所有让其对象图保持可达的实时引用，留下可以解析的休眠身份，并在下一次受支持操作时从持久化数据重建一个实时实例。

不要把驻留日志分层或驻留分片压紧作为并行工作安排。只有整会话驱逐后活动会话仍然过大时，才重新评估日志分层；部分日志与当前同步 `events`、序列索引、surface、fork、导出和观察者约定冲突。只有测量把分片对象确定为剩余成本时，才重新评估驻留分片压紧；存储编解码器已经打包分片，而内存中的打包表示需要一个保留精确回放与序列身份的虚拟事件视图。现有分析器为这些决策提供估算，而非实现。

直接的集成步骤是指定部署所有者，在该组合中组装压力／策略／缓存释放链，并记录其工作负载的基准测试结果。在此之前，保持这些包为可选，并把它们描述为测量与策略 seam，而不是通用内存管理功能。

## Alternatives considered

**止于缓存释放。** 这是风险最低的默认方案，对中等工作负载可能足够，但当事件日志主导长寿命会话时，它不能限制内存。将它保留为已交付行为，而不是完整驱逐已经完成的证明。

**先实现日志分层或分片压紧。** 这些机制可以帮助一个大型活动会话，但会把部分日志表示引入围绕单一连续同步数组构建的约定。整会话驱逐保留现有 `Session` 表示，应获得基准测试优先级。

**把上下文压缩或 MemPalace 用作回收。** 上下文压缩改变模型可见 surface，同时保留被遮蔽的原始事件；MemPalace 存储语义长期记忆。两者都不移除驻留会话日志。

**直接在压力检测器或驻留策略内驱逐。** 这会把检测或选择与持久化及存储生命周期耦合。现有检测器、策略和执行器边界保持可替换性，仍是正确的所有权划分。

## Acceptance criteria

- 一个有代表性的长时间运行组合通过已交付宿主基准测试或等价进程测量证明，相比只释放缓存，完整驱逐能进一步显著改善 RSS 或堆。
- 没有开放轮次的空闲会话在其驻留对象图变为不可达之前到达持久存储；持久化失败时，驱逐失败且不丢弃实时实例。
- 下一次受支持的查找或操作只再水合一个实时会话，其事件、surface、派生消息、header 与序列延续都匹配驱逐前状态。
- 生命周期、并发访问、fork／导出与 dispose 语义得到明确说明与测试；陈旧 `Session` 引用不能向替代实例追加事件。
- 文档继续把内存压力与分析器标记为信号和测量，绝不标记为回收。

## Risks

透明再水合跨越当前由 fiber 拥有的会话与 agent 生命周期。保留的对象引用可能阻止垃圾回收，或让一个会话身份分裂到两个实例；压力触发的持久性检查点也可能增加延迟，或在同一资源压力下失败。存储代理或休眠项还可能把同步 API 扩大为异步 API。如果目标组合无法在不削弱会话身份与追加顺序的前提下定义这些语义，就保留缓存释放并否决完整驱逐，而不是隐藏冲突。
